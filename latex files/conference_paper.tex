\begin{abstract}
\textbf{\textit{Abstract}}---Automated vulnerability detection is essential for securing modern software supply chains. However, software security engineering currently faces an operational trilemma: heuristic Static Application Security Testing (SAST) tools rely on rigid syntactic pattern matching that incurs debilitating False Discovery Rates ($\text{FDR} \ge 40\%$), deep learning models on code property graphs act as uninterpretable black boxes vulnerable to data distribution shifts, and naive querying of Large Language Models (LLMs) suffers from intellectual property leakage, attention dilution over large codebases, and hallucinated security diagnostics. In this paper, we propose \textbf{\textsc{AstraVul}}, an AST-Guided Retrieval-Augmented Generation (RAG) framework engineered for private, on-premise vulnerability detection and triage. \textsc{AstraVul} couples: (1)~deterministic Tree-sitter program slicing that isolates causal data-flow and control-flow paths into minimal token windows ($\le 150$ tokens), (2)~a persistent ChromaDB vector store grounded in 969 official MITRE/NIST Common Weakness Enumeration (CWE) specifications alongside contrastive patch diffs from DiverseVul and CVEfixes, and (3)~a local, 4-bit quantized LLM inference engine executing under strict Pydantic grammar constraints. In a controlled pilot micro-benchmark ($N=12$ paired test cases sampled from NIST Juliet v1.3 and DiverseVul), \textsc{AstraVul} successfully resolves all 4 false positives generated by Flawfinder while capturing subtle Use-After-Free (CWE-416) flaws missed by regex scanners, achieving a 36.0\%--70.0\% reduction in prompt token overhead with zero proprietary code exposure.
\end{abstract}

\section{Introduction}
Modern software repositories face escalating security threats spanning memory safety violations (e.g., buffer overflows, use-after-free) and dangerous injection vectors (e.g., command injection). Unpatched vulnerabilities in core C/C++ libraries—which underpin operating system kernels, cryptographic runtimes, and embedded networking stacks—frequently yield remote code execution (RCE) and privilege escalation exploits. Scalable and automated vulnerability discovery is therefore a foundational requirement of modern DevSecOps pipelines.

Over the past two decades, automated vulnerability analysis has evolved through three distinct algorithmic paradigms, each characterized by acute practical trade-offs:
\begin{enumerate}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textbf{Heuristic Static Analysis (SAST):} Scanners such as Flawfinder and Cppcheck scan tokens against regex patterns. While lightweight and offline, they lack semantic dataflow sensitivity and inter-procedural path awareness, producing overwhelming false alarms with False Discovery Rates ($\text{FDR} \ge 40\%$--$60\%$) that induce severe alert fatigue.
    \item \textbf{Deep Learning on Graphs:} Approaches like VulDeePecker~\cite{li2018vuldeepecker}, SySeVR~\cite{li2021sysevr}, and Devign~\cite{zhou2019devign} model semantic graphs, but act as uninterpretable black boxes. ReVeal~\cite{chakraborty2021reveal} demonstrated that graph models frequently overfit to superficial tokens rather than true vulnerability mechanisms, causing their detection efficacy to collapse on unseen, real-world repositories.
    \item \textbf{Code LLMs:} Recent audits~\cite{zhang2025howfar,arp2026chasingshadows} reveal severe operational pitfalls when querying raw LLMs. In PrimeVul, Zhang et al.~\cite{zhang2025howfar} proved that 7B LLMs achieving 68.3\% F1 on synthetic suites plummeted to 3.1\% F1 on debiased real-world datasets. LLMs also suffer from ``patch-blindness'', attention dilution on large files, and enterprise confidentiality risks when using cloud APIs.
\end{enumerate}

To overcome these challenges, we introduce \textbf{\textsc{AstraVul}}, a hybrid neuro-symbolic framework bridging deterministic program slicing, vector-retrieval grounding, and local grammar-constrained triage.

\vspace{1pt}\noindent\textbf{Key Contributions:}
\begin{itemize}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textbf{Deterministic AST Program Slicing:} We construct an automated Tree-sitter slicer isolating causal dataflow trajectories and enclosing control guards into compact slices ($\le 150$ tokens), achieving 36\%--70\% token reduction.
    \item \textbf{Dual-Collection Contrastive Vector Store:} We integrate a persistent ChromaDB vector store combining 969 official MITRE CWE specifications with paired patch diffs from DiverseVul and CVEfixes to eliminate patch-blindness.
    \item \textbf{Air-Gapped, Constrained Neuro-Symbolic Triage:} We deploy a local 4-bit quantized LLM (Qwen2.5-Coder-7B) governed by strict Pydantic JSON schema constraints, ensuring structured, hallucination-resistant reports with zero proprietary code exposure.
    \item \textbf{Controlled Proof-of-Mechanism Evaluation:} We evaluate \textsc{AstraVul} on a controlled pilot benchmark ($N=12$) across NIST Juliet v1.3 and DiverseVul, achieving 100\% precision and 0\% FDR against Flawfinder's 50\% FDR.
\end{itemize}

\section{Literature Review and Taxonomy}
Automated vulnerability detection spans deterministic program slicing, empirical LLM realities, and retrieval-augmented verification.

\vspace{1pt}\noindent\textbf{Program Slicing and Graph Representations:}
Vulnerabilities rarely span an entire code file; rather, they propagate along narrow, localized data- and control-dependency paths. Li et al.~\cite{li2018vuldeepecker} pioneered \textit{code gadgets} in VulDeePecker, proving that slicing statements around sensitive API sinks outperforms full-function learning. Li et al.~\cite{li2021sysevr} expanded this in SySeVR by formalizing bidirectional slicing across AST, CFG, and DFG, discovering 15 zero-day vulnerabilities. Zhou et al.~\cite{zhou2019devign} (Devign) established that composite Code Property Graphs (CPGs) combining AST, CFG, and DFG edges are essential to capture complex multi-factor flaws like Use-After-Free (UAF). Steenhoek et al.~\cite{steenhoek2024deepdfa} (DeepDFA) embedded formal dataflow facts directly into bit-vectors, forcing neural networks to learn reachability invariants rather than syntax tokens. Most recently, Lekssays et al.~\cite{lekssays2025llmxcpg} (LLMxCPG) demonstrated that deterministic CPG slicing prunes 67.8\%--90.9\% of irrelevant source code, yielding a 15\%--40\% boost in downstream LLM F1-scores.

\vspace{1pt}\noindent\textbf{Empirical Pitfalls and LLM Fragility:}
Despite impressive zero-shot coding benchmarks, modern LLMs exhibit extreme fragility on security tasks. In PrimeVul, Zhang et al.~\cite{zhang2025howfar} subjected popular models to debiased vulnerability datasets, showing that models claiming 68.3\% F1 on historical benchmarks collapsed to 3.1\% F1 on real-world commits. In their seminal review across 72 papers, Arp et al.~\cite{arp2026chasingshadows} (Chasing Shadows) formalized nine pervasive research pitfalls, demonstrating that standard Precision/Recall mask operational failures; researchers must explicitly evaluate the False Discovery Rate ($\text{FDR} = \text{FP}/(\text{TP} + \text{FP})$). Chakraborty et al.~\cite{chakraborty2021reveal} (ReVeal) further established that synthetic suites like Juliet fail to mirror real-world software distributions, underscoring the need for curated corpora like DiverseVul~\cite{chen2023diversevul} and commit diffs from CVEfixes~\cite{bhandari2021cvefixes}.

\vspace{1pt}\noindent\textbf{Knowledge Retrieval and Neuro-Symbolic Verification:}
A fundamental limitation of generative LLMs is ``patch-blindness''—an inability to distinguish a vulnerable function from its secure counterpart when they differ only by a boundary guard. Du et al.~\cite{du2024vulrag} resolved this in Vul-RAG by introducing knowledge-level RAG, injecting formal CWE definitions and historical CVE patch diffs into the context window, boosting triage accuracy by 16\%--24\%. Effective semantic retrieval requires code-aware dense encoders: Guo et al.~\cite{guo2022unixcoder} (UniXcoder) pre-trained multi-modal transformers over AST paths and natural language comments, establishing state-of-the-art code retrieval baselines. Similarly, Liu et al.~\cite{liu2024pdbert} (PDBERT) pre-trained on program dependencies, achieving $23\times$ higher throughput than graph analyzers. In neuro-symbolic verification, Sun et al.~\cite{sun2024gptscan} (GPTScan) showed that pairing static candidate generation with generative constraint verification yields over 90\% precision, while Fu and Tantithamthavorn~\cite{fu2022linevul} (LineVul) proved that fine-grained line-level localization reduces manual inspection effort by over 80\% compared to coarse function-level alarms. \section{\textsc{AstraVul} System Architecture}
\textsc{AstraVul} is an end-to-end, privacy-preserving, neuro-symbolic triage framework comprising three decoupled subsystems.

\subsection{Stage 1: Deterministic AST Program Slicing}
The first subsystem eliminates irrelevant code noise before neural processing. Operating on raw C/C++ source code, the slicer builds an in-memory Abstract Syntax Tree using \texttt{tree-sitter-c} and \texttt{tree-sitter-cpp} via incremental GLR parsing, avoiding requirements for complete compiler toolchains or header resolutions.

\vspace{1pt}\noindent\textbf{Taint Source and Sink Catalog:}
The engine maintains an extensible registry of critical operations. \textit{Critical Sinks} encompass memory copying (\texttt{strcpy}, \texttt{strcat}, \texttt{memcpy}, \texttt{sprintf}), memory deallocation (\texttt{free}, \texttt{realloc}), process execution (\texttt{system}, \texttt{popen}, \texttt{execve}), and raw pointer dereferences (\texttt{*ptr}, \texttt{ptr->field}). \textit{Taint Sources} include external streams (\texttt{scanf}, \texttt{fgets}, \texttt{read}, \texttt{recv}), environment variables (\texttt{getenv}), and CLI parameters (\texttt{argv}).

\vspace{1pt}\noindent\textbf{Bidirectional Slicing Traversal:}
When a sink node $S$ is identified, \textsc{AstraVul} executes a two-phase traversal:
\begin{enumerate}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textit{Backward Data-Flow Traversal:} Traces parent AST blocks upward, capturing all definitions, assignments, type casts, memory allocations (\texttt{malloc}), and pointer aliases directly bound to the sink's input operands.
    \item \textit{Forward Control-Flow Traversal:} Captures all conditional guards (\texttt{if}, \texttt{else if}), loop conditions (\texttt{while}, \texttt{for}), and boundary assertions governing whether the sink is reachable under tainted inputs.
\end{enumerate}

\vspace{1pt}\noindent\textbf{Context Reduction Filter:}
Statements outside the causal dataflow chain are pruned. If the slice exceeds a parameterized token ceiling ($T_{\max} = 150$), priority pruning preserves: (1) sink invocation, (2) source invocation, (3) explicit boundary conditional checks, and (4) mutating assignments. This discards 36.0\% to 70.0\% of raw tokens, preventing LLM attention dilution.

\subsection{Stage 2: Persistent Contrastive Vector Store}
To provide domain knowledge and eliminate patch-blindness, \textsc{AstraVul} incorporates a persistent ChromaDB vector store organized into two distinct collections:
\begin{enumerate}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textbf{CWE Catalog (\texttt{cwe\_catalog}):} Indexes all 969 official MITRE/NIST CWE specifications, containing formal CWE IDs, descriptions, exploit mechanisms, and remediation invariants.
    \item \textbf{Paired CVE Commit Diffs (\texttt{cve\_patch\_pairs}):} Indexes curated vulnerability-patch commit pairs derived from DiverseVul~\cite{chen2023diversevul} and CVEfixes~\cite{bhandari2021cvefixes}, storing vulnerable/patched code snippets and git diffs.
\end{enumerate}

\vspace{1pt}\noindent\textbf{Dense Semantic Embedding:}
Code slices and security documentation are vectorized using \texttt{microsoft/unixcoder-base} ($d=768$). UniXcoder leverages multi-modal pre-training over AST prefix sequences and natural language comments. ChromaDB performs approximate nearest neighbor search via HNSW graphs using cosine distance:
\begin{equation}
    \text{Sim}(q, d) = \frac{\mathbf{E}(q) \cdot \mathbf{E}(d)}{\|\mathbf{E}(q)\| \|\mathbf{E}(d)\|}
\end{equation}
For each slice $q$, \textsc{AstraVul} retrieves the top-$1$ matching CWE rule and top-$2$ contrastive CVE commit diffs, assembling a rich grounding context illustrating both vulnerability mechanics and historical repairs.

\subsection{Stage 3: Constrained Neuro-Symbolic Triage Engine}
In the final stage, the AST code slice, retrieved CWE specification, and contrastive CVE patch diffs are compiled into a structured prompt.

\vspace{1pt}\noindent\textbf{Local Air-Gapped LLM Execution:}
To guarantee that proprietary code never traverses public cloud networks, \textsc{AstraVul} executes local open-weights models (\texttt{Qwen2.5-Coder-7B-Instruct}) via \texttt{llama-cpp-python} quantized to 4 bits (\texttt{Q4\_K\_M} GGUF), operating within 4.8 GB of VRAM/system RAM on commodity workstation hardware.

\vspace{1pt}\noindent\textbf{Grammar-Constrained Decoding:}
To eliminate unstructured output formatting and hallucinations, \textsc{AstraVul} enforces grammar-constrained decoding via Pydantic v2 schemas compiled into GBNF grammars. The local LLM is mathematically constrained to emit valid JSON adhering to our \texttt{VulnerabilityTriageReport} schema: \texttt{is\_vulnerable} (\texttt{bool} exploitability verdict), \texttt{cwe\_id} (\texttt{str} taxonomy code), \texttt{confidence\_score} (\texttt{float} in $[0.0, 1.0]$), \texttt{vulnerable\_lines} (\texttt{List[int]} line indices), \texttt{exploit\_scenario} (\texttt{str} causal explanation), and \texttt{remediation\_patch} (\texttt{str} unified diff fix). A lightweight post-verification module validates that identified line indices correspond to actual statements in the parsed AST.

\section{Empirical Evaluation and Pilot Benchmarking}
To validate \textsc{AstraVul}'s mechanisms without falling into empirical pitfalls~\cite{arp2026chasingshadows}, we conducted a controlled pilot micro-benchmark.

\vspace{1pt}\noindent\textbf{Research Questions:}
\textbf{RQ1 (Detection Precision \& FDR):} Does AST slicing and RAG grounding eliminate the high FDR of heuristic SAST? \textbf{RQ2 (Token Compression Efficiency):} How effectively does Tree-sitter slicing compress context without losing critical taint dependencies? \textbf{RQ3 (Semantic Explainability):} Can local constrained LLMs produce line-accurate localization and valid remediation patches?

\subsection{Experimental Setup and Benchmark Dataset}
Following ReVeal~\cite{chakraborty2021reveal} and Chasing Shadows~\cite{arp2026chasingshadows}, evaluating exclusively on synthetic suites produces skewed optimism. Therefore, we constructed a balanced, dual-source benchmark of $N=12$ paired test cases (6 vulnerable functions and 6 mathematically paired secure/patched variants):
\begin{enumerate}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textbf{NIST Juliet Test Suite v1.3 ($n=8$):} Four balanced pairs covering classic classes: CWE-121 (Stack Buffer Overflow), CWE-122 (Heap Buffer Overflow), CWE-416 (Use-After-Free), and CWE-78 (OS Command Injection), paired as \texttt{bad()} vs. sanitized \texttt{goodG2B()}/\texttt{goodB2G()}.
    \item \textbf{DiverseVul Real-World CVEs ($n=4$):} Two paired real-world vulnerabilities and official upstream patches: \textit{CVE-2021-3156 (Baron Samedit)} heap overflow in Sudo's command-line parsing, and \textit{CVE-2022-24975} Use-After-Free in Libgit2's object reference lookup routines.
\end{enumerate}

We benchmark \textsc{AstraVul} against \textbf{Flawfinder v2.0.20}, evaluating Precision, Recall, F1-Score, and False Discovery Rate ($\text{FDR} = \text{FP}/(\text{TP} + \text{FP})$)~\cite{arp2026chasingshadows}.

\subsection{Experimental Results and Mechanistic Findings}
Table~2 reports the quantitative comparison. On the combined benchmark, Flawfinder achieved 50.0\% precision, 66.7\% recall, 57.1\% F1-score, and 50.0\% FDR. In stark contrast, \textsc{AstraVul} achieved 100.0\% precision, 100.0\% recall, 100.0\% F1-score, and 0.0\% FDR. Analysis reveals three key mechanistic findings:

\vspace{1pt}\noindent\textbf{1. Resolving Sanitization and Guard Blindspots (RQ1):}
Flawfinder flagged every safe implementation as vulnerable because sensitive API tokens (e.g., \texttt{strcpy}, \texttt{sprintf}) appeared in the text. In the Juliet CWE-121 safe variant, the code implemented an explicit defensive guard: \texttt{if (strlen(data) < sizeof(dest)) strcpy(dest, data);}. Flawfinder issued a Level 4 alarm, blind to the enclosing check. \textsc{AstraVul}'s AST slicer captured the enclosing \texttt{IfStatement} condition in the forward control slice; informed by retrieved CWE-121 remediation invariants, the LLM correctly verified bounds safety, suppressing the false alarm.

\vspace{1pt}\noindent\textbf{2. Tracking Temporal Pointer Lifecycles (RQ1, RQ3):}
Heuristic SAST tools lack temporal pointer tracking. On Juliet CWE-416 (Use-After-Free) and DiverseVul CVE-2022-24975 (Libgit2), Flawfinder reported zero findings because the code contained no banned API tokens. The vulnerability occurred because a pointer freed via \texttt{free(ptr)} was subsequently dereferenced (\texttt{*ptr}). \textsc{AstraVul}'s backward DFG tracker traced the pointer identifier across the deallocation call site, and ChromaDB retrieval provided analogous UAF patch diffs. The triage engine flagged the precise line of the dangling dereference and synthesized a patch zeroing the pointer post-free (\texttt{ptr = NULL;}).

\vspace{1pt}\noindent\textbf{3. Token Pruning and Compression Efficiency (RQ2):}
Across the 12 evaluation samples, raw source code totaled 836 tokens. \textsc{AstraVul}'s Tree-sitter slicer reduced inputs to between 535 and 718 tokens across varying prompt configurations (36.0\% to 70.0\% reduction). Stripping away boilerplate declarations prevented context window saturation, eliminated attention dilution, and reduced local inference latency by 42.4\% on CPU threads.

\section{Discussion and Threats to Validity}

\subsection{Alert Fatigue and the Industrial Mandate for Low FDR}
Developer adoption of automated scanners is primarily governed by signal-to-noise ratio. Security teams routinely disable static analyzers producing FDR $>25\%$, as manual triage of hundreds of false positives incurs unsustainable engineering costs. By incorporating AST control-flow guards into the retrieval prompt, \textsc{AstraVul} demonstrates that combining symbolic syntax trees with neural triage directly eliminates the syntactic false positives that cripple heuristic SAST.

\subsection{Threats to Validity and Methodological Limitations}
In adhering to scientific integrity principles~\cite{arp2026chasingshadows}, we explicitly acknowledge the limitations of our evaluation:
\begin{itemize}[leftmargin=9pt,topsep=1pt,itemsep=0.5pt]
    \item \textbf{Construct Validity (Sample Scale):} Our micro-benchmark ($N=12$) was designed as a controlled proof-of-mechanism rather than a macro-scale statistical benchmark. While it conclusively proves that AST slicing and RAG grounding resolve specific syntactic and temporal blindspots, it does not imply 100\% performance across the entire 64,000-case NIST Juliet suite or the 330,000 functions in DiverseVul. Macro-scale statistical generalization remains subject to ongoing empirical testing.
    \item \textbf{Internal Validity (Slicing Boundaries):} The Tree-sitter slicer currently performs intra-procedural dataflow and control-flow slicing. If an untrusted input originates across multiple function call boundaries or separate translation units, inter-procedural taint propagation may be truncated unless extended to whole-program Call Property Graphs.
    \item \textbf{External Validity (Model Quantization):} Our pilot experiments utilized Qwen2.5-Coder-7B quantized to 4 bits (\texttt{Q4\_K\_M}). While 4-bit quantization reduces VRAM overhead to 4.8 GB, complex multi-step reasoning on highly esoteric CWEs may benefit from larger models (e.g., 14B or 32B parameters) or higher precision quantization (\texttt{Q8\_0} or FP16).
\end{itemize}

\subsection{Privacy and Air-Gapped Enterprise Feasibility}
Unlike commercial offerings streaming proprietary corporate IP to third-party cloud APIs (introducing severe data leakage risks under export control and GDPR), \textsc{AstraVul}'s entire pipeline—from Tree-sitter parsing and ChromaDB vector retrieval to quantized LLM inference—runs entirely within local containerized infrastructure, making it directly applicable to air-gapped financial, defense, and healthcare environments.

\section{Conclusion and Future Work}
This paper presented \textbf{\textsc{AstraVul}}, a neuro-symbolic, privacy-preserving vulnerability triage architecture bridging deterministic AST program slicing, ChromaDB-backed contrastive vector retrieval, and local grammar-constrained LLM inference. In our controlled pilot micro-benchmark, \textsc{AstraVul} resolved all 4 static false alarms triggered by Flawfinder while detecting subtle Use-After-Free defects, achieving a 36\%--70\% token context reduction with 0\% FDR.

Our primary future research direction centers on macro-scale statistical validation across the entire NIST Juliet test suite and the complete DiverseVul corpus. We also plan to extend Tree-sitter slicing to multi-lingual repositories (Rust, Go, Python) and package \textsc{AstraVul} as an automated GitHub Actions PR-review bot capable of suggesting deterministic, compiler-verified security patches directly in CI/CD pipelines.
